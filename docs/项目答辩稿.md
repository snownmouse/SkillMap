## 一、项目背景与选题依据

### 1.1 时代背景

当前我国正处于从"人口红利"向"人才红利"转型的关键阶段。教育部明确提出要"构建中国特色生涯教育自主知识体系"，强调将**立德树人、为党育人、为国育才**作为教育的根本任务。

与此同时，AI 大模型技术的爆发为个性化教育带来了前所未有的可能——传统"千人一面"的课程表可以被"千人千面"的智能学习路径所取代。

### 1.2 选题依据

本项目的选题基于三个核心判断：

1. **需求真实**：大学生和职场新人普遍面临"不知道该学什么、先学什么、后学什么"的迷茫
2. **技术可行**：大语言模型能够基于用户输入生成结构化、个性化的学习方案
3. **理论创新空间**：现有生涯教育工具多为西方理论主导，缺乏中国特色的理论融合

### 1.3 产品定位

**SkillMap 是一款对话驱动的 AI 技能探索与生涯规划平台**——以"技能树"为核心隐喻，帮助用户从"认知自我"到"规划未来"。

## 二、行业痛点与需求分析

### 2.1 传统学习规划的四大痛点

| 痛点 | 具体表现 | 用户损失 |
|------|---------|---------|
| **路径不清晰** | 课程目录≠成长路径，用户不知道技能之间的先后依赖关系 | 学习效率低，容易走弯路 |
| **方案不个性** | 所有人用同一套课程大纲，不区分专业背景、目标职业和当前水平 | 基础好的人浪费时间，基础差的跟不上 |
| **反馈不及时** | 学完了不知道自己掌握到什么程度，缺乏结构化复盘机制 | 虚假的"学完了"，真实的一知半解 |
| **规划不落地** | 职业规划停留在"性格测试"层面，缺少可执行的具体步骤 | 知道方向，不知道怎么走 |

### 2.2 现有产品的局限性

- **职业测评类产品**（如 MBTI、霍兰德测试）：只有匹配结果，没有学习路径
- **在线课程平台**（如 Coursera、B站）：课程列表是线性的，不展示技能间的拓扑关系
- **AI 对话工具**（如 ChatGPT）：回答泛化，缺乏围绕技能体系的深度互动

**SkillMap 的核心突破**：将"职业测评 → 技能树生成 → 节点对话复盘 → 进度追踪"串成闭环，填补了从"知道方向"到"走到目标"之间的空白。

## 三、解决方案概述

### 3.1 核心思路

```
用户输入（专业 + 目标职业 + 当前水平）
     ↓
AI 智能生成个性化技能树（25-40 个节点，含依赖关系）
     ↓
```

## 四、核心功能展示

### 4.1 智能技能树生成

**输入**：用户填写专业、目标职业、当前水平、每周学习时长、已有技能、备注

**输出**：一棵包含 25-40 个节点的结构化技能树，每个节点包含：
- 节点名称、描述、为什么重要
- 难度等级（初级/中级/高级）
- 认知层级（Bloom's Taxonomy 六层）
- 学习目标、交付物、学习资源
- 推荐工具、实践技巧、常见陷阱
- 掌握标准（最低合格 / 熟练 / 精通）
- 预估学习时长

**关键技术**：提示词工程融合了 Bloom's Taxonomy、认知负荷理论、建构主义、最近发展区等教育理论

### 4.2 可视化技能图谱

- 使用 **Cytoscape.js** 渲染为交互式网络图
- 节点颜色区分技能类别（核心 / 专业 / 通用）
- 节点样式区分学习状态（未解锁 / 可学习 / 学习中 / 已完成）
- 方向箭头展示技能前置依赖关系
- 支持缩放、拖拽、点击查看详情
- Motion 动画库实现流畅过渡效果

### 4.3 节点对话复盘

- 每个技能节点拥有独立的 AI 对话空间
- 对话上下文锚定在当前技能领域，回答更聚焦
- 对话心得可回写至节点进度，形成"学习→复盘→进步"的正循环
- 历史对话持久化存储，可随时回溯

### 4.4 职业路径规划

基于 8 个维度（霍兰德匹配、职业锚匹配、家国情怀、义利兼顾、明德弘道、实践志向、国家战略需求、社会贡献预期）的加权评分，为用户推荐 7 条差异化成长路径：

- 技术深耕路线 → 国家战略：科技自立自强
- 管理发展路线 → 高素质管理人才培养
- 复合发展路线 → 跨界复合型人才
- 基层锻炼路线 → 乡村振兴
- 国家战略路线 → 重点领域突破
- 创新创业路线 → 大众创业
- 稳定发展路线 → 公共服务

### 4.5 学习时间线

将用户的技能解锁、节点完成、对话复盘等事件按时间轴展示，形成可视化的成长轨迹。

## 五、理论创新——中国特色生涯规划体系

### 5.1 为什么要做理论创新

现有生涯教育工具几乎全部基于西方理论（Holland Code、Career Anchors 等），缺乏与中国教育理念的结合。在"立德树人"的根本任务下，生涯规划不能只关注个人兴趣匹配，需要融入**社会责任感与国家战略视野**。

### 5.2 "个人—社会—国家"三位一体框架

```
┌─────────────────────────────────────────────┐
│           中国特色生涯规划体系               │
├─────────────────────────────────────────────┤
│  ┌───────────┐  ┌───────────┐  ┌─────────┐ │
│  │  个人维度  │  │  社会维度  │  │ 国家维度 │ │
│  │ (西方理论) │  │ (中西融合) │  │(中国特色)│ │
│  └───────────┘  └───────────┘  └─────────┘ │
│  · 兴趣匹配    · 社会责任     · 国家战略   │
│  · 能力评估    · 职业道德     · 区域协调   │
│  · 价值取向    · 义利兼顾     · 基层锻炼   │
│  · 目标设定    · 家国情怀     · 民族复兴   │
└─────────────────────────────────────────────┘
```

### 5.3 中西理论融合对照

| 维度类型 | 理论来源 | 评估内容 |
|---------|---------|---------|
| 霍兰德匹配度 | Holland Code（西方） | 职业兴趣匹配 |
| 职业锚匹配度 | Career Anchors（西方） | 价值观契合度 |
| 家国情怀 | 中华优秀传统文化 | 服务国家意愿 |
| 义利兼顾 | 中华优秀传统文化 | 利益与责任平衡 |
| 明德弘道 | 中华优秀传统文化 | 职业道德修养 |
| 实践志向 | 马克思主义 | 基层实践意愿 |
| 国家战略需求 | 社会主义教育理论 | 战略契合度 |
| 社会贡献预期 | 马克思主义人的全面发展 | 社会贡献价值 |

### 5.4 理论创新核心原则

1. **中体西用**：以中国特色理论为主体框架，融合西方科学方法
2. **知行合一**：理论指导与实践锻炼并重
3. **家国同构**：个人发展与国家命运紧密相连
4. **双层分离**：数据处理理论（精确计算）≠ 用户展示理论（通俗解释）

## 六、技术架构与创新点

### 6.1 技术栈一览

| 层级 | 技术选型 |
|------|---------|
| 前端 | React 19 · TypeScript · Vite · Tailwind CSS v4 · Cytoscape.js · Motion |
| 后端 | Node.js · Express · TypeScript |
| 数据库 | SQLite（开发）· PostgreSQL（生产）· 版本化迁移 |
| 队列/缓存 | Redis Stream · Redis PubSub |
| AI 模型 | Ark · DeepSeek · SiliconFlow · Gemini · Qwen · 自定义 OpenAI 兼容 |
| 部署 | Docker Compose · PM2 · GitHub Actions CI/CD |

### 6.2 八大技术创新点

#### 创新点 1：多模型熔断切换机制

实现了统一的 LLM 适配层（Provider Pattern），支持 6 种以上 AI 模型的一键切换与自动容灾：

- 主提供商不可用时，自动切换至备用提供商
- 内置调用日志与 Token 用量统计
- 支持 Dummy Provider 用于离线开发和测试

#### 创新点 2：异步任务队列 + WebSocket 实时推送

技能树生成属于长耗时 LLM 调用，系统采用异步任务架构：

```
用户请求 → 创建任务（落库）
       ↓
  Redis Stream 入队
       ↓
  Worker 独立进程消费
       ↓
  执行完成 → DB + WebSocket 推送
       ↓
  前端实时订阅/轮询获取结果
```

关键机制：
- 任务状态全生命周期追踪（pending → processing → completed → failed）
- Redis PubSub 跨实例广播，多实例部署无缝协作
- 数据库租约防重复执行，服务重启自动恢复
- 指数退避自动重试 + 定时调度器

#### 创新点 3：双数据库自适应模式

| 模式 | 数据库 | 触发条件 |
|------|--------|---------|
| 开发模式 | SQLite | 默认，`DB_PATH` 配置，零依赖 |
| 生产模式 | PostgreSQL | `NODE_ENV=staging|production` 强制启用 |

- 4 个版本化迁移脚本，支持升级/回滚
- 服务启动自动执行未应用迁移
- 环境自适应，无需手动切换

#### 创新点 4：多层安全防护

| 防护层 | 机制 |
|--------|------|
| 身份认证 | Bearer Token + Refresh Token 双令牌 + HttpOnly Cookie 访客会话 |
| 密码安全 | bcrypt 哈希 + 旧 SHA-256 渐进式迁移 |
| Token 安全 | `h1:sha256(rawToken)` 哈希存储，防库泄露接管 |
| API 限流 | 15 分钟窗口，支持 Redis store / 内存降级 |
| 输入安全 | XSS 清洗 + Prompt Injection 防护 |
| 响应安全 | CSP / X-Frame-Options / X-Content-Type-Options 安全头 |
| WS 安全 | Origin 白名单 + Task 归属校验 + 连接/消息限流 |
| 请求追踪 | 全局 Trace ID，全链路可审计 |

#### 创新点 5：JSON 增量解析 + 自动修复

大语言模型的 JSON 输出天然存在格式不稳定、不完整、字段遗漏的问题。系统自研了两大工具：

- **IncrementalJsonParser**：支持流式增量解析，边接收边渲染，用户体感延迟大幅降低
- **JsonRepairUtils**：自动修复缺失引号、多余逗号、截断、未闭合括号等常见 JSON 格式错误

#### 创新点 6：前后端一体化 + 进程分离

- **开发阶段**：单进程 Express + Vite 中间件，HMR 热更新秒级响应
- **生产阶段**：API 进程 + Worker 进程分离，互不阻塞

```yaml
# docker-compose.yml
services:
  app:      # API + HTTP + WS
  worker:   # Redis Stream consumer (独立扩缩)
  postgres: # 数据库
  redis:    # 队列 + PubSub + 限流 store
```

#### 创新点 7：语音交互能力

内置 `useVoiceInput`（STT）和 `useVoiceOutput`（TTS）两个自定义 Hook，拓展无障碍使用场景。

#### 创新点 8：提示词工程深度融合教育理论

提示词模板整合了 Bloom's Taxonomy、建构主义、联通主义、认知负荷理论、刻意练习、OKR 目标管理等 7+ 教育理论，确保 AI 输出的技能树兼具科学性与实用性。

#### 创新点 9：国家职业标准知识锚定

面对专家对"AI 生成内容可靠性"的普遍关切，系统引入三层知识保障架构：

```
┌──────────────────────────────────────────────────────────────┐
│                  SkillMap 三层数据架构                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  L1: 国家职业分类框架（权威不可辩驳）                          │
│  ─────────────────────────────────                            │
│  数据源：《国家职业分类大典（2022年版）》——人社部发布          │
│  覆盖：8 大类、79 中类、449 小类、1636 个具体职业              │
│  每职业含：编码、名称、定义描述                                │
│  标注：97 个数字职业（S）、133 个绿色职业（L）                  │
│                                                              │
│  L2: 国家战略人才需求（真实市场信息）                          │
│  ─────────────────────────────────                            │
│  数据源：粤港澳大湾区人才需求目录、北京市新质生产力人力资源目录    │
│          人社部人才需求目录、各地紧缺技能人才目录                │
│  覆盖：20+ 紧缺产业的 24 个代表性岗位                          │
│  作用：为每个职业提供人才紧缺程度和区域分布参考                   │
│                                                              │
│  L3: LLM 在框架内做个性化扩展                                  │
│  ─────────────────────────────────                            │
│  来源：AI 实时生成                                            │
│  约束：不能偏离 L1 的职业定义范围，标注来源字段                  │
│  数据入库至 skill_terms 表，支持审核和回写                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**实现机制**：
- 建表 `career_classification` + `talent_demand`，版本化迁移（0005）
- `CareerClassificationService`：职业匹配 + 层级路径查询 + 人才需求查询
- 技能树生成时自动注入国家数据到 prompt（`injectToPrompt`），作为 LLM 生成锚点
- 服务层带 try-catch 兜底，数据为空时自动跳过，不影响现有流程

**核心价值**：
- 每一个目标职业在国家标准中都有"合法身份"和官方定义
- 人才需求数据来源为国家人社部及各地发布的公开目录，非 AI 生成、不可辩驳
- 专家质疑时可以回答："我们的数据来源不是 AI 编的，是国家职业分类大典和人才需求目录"

## 十一、答辩 Q&A（预设专家问答）

### Q1：你们的内容都是 AI 生成的，怎么保证可靠性？有没有本地数据源做支撑？

**A**：我们采用三层数据架构来保障内容可靠性。

**第一层**——国家职业分类框架。系统内置了《国家职业分类大典（2022年版）》的 1636 个职业数据，每一个目标职业在国家标准中都有官方编码、名称和定义。这是人社部发布的国家标准，来源不可辩驳。

**第二层**——国家战略人才需求。我们从国家人社部及各地发布的公开人才需求目录中提取了 24 个紧缺产业方向的人才需求数据，包括粤港澳大湾区人才需求目录、北京市新质生产力人力资源目录等。这些数据不是 AI 生成的，是官方发布的真实市场信息。

**第三层**——AI 在框架内做个性化扩展。在 LLM 生成技能树时，我们先将前两层的国家数据注入到 prompt 中作为"锚点"，LLM 只能在国家定义的职业框架内做个性化细化。生成的内容不会偏离国家职业标准。

简单说：**顶层框架是国家标准定的，方向判断是官方数据给的，个性化细节是 AI 扩展的。**

### Q2：你们没有自己的技能数据库，怎么保证内容不过时？

**A**：这正是我们选择"AI 生成 + 国家锚点"而不是"静态数据库"的原因。

静态数据库是"死的"——一旦入库，就得手动维护更新。而我们的架构是动态的：
- **国家职业大典**每 7 年更新一次，数据变更频率极低，一次入库长期有效
- **人才需求目录**每年更新，我们只需要重新跑一遍 seed 脚本即可同步
- **具体技能内容**由 LLM 实时生成，模型本身的知识就是最新的

换句话说，**我们不需要自己维护一个"大而全"的技能数据库——国家数据给我们框架，LLM 给我们时效性。**

### Q3：LLM 生成的 JSON 格式不稳定怎么办？会不会经常出错误？

**A**：这个问题我们在工程上做了充分的防御。

LLM 输出 JSON 不稳定是一个行业共性难题，我们的 JSON 增量解析引擎（IncrementalJsonParser）和智能修复工具（smartFixJson）包含 7 层容错策略：
1. 直接解析
2. 提取 Markdown 代码块
3. 提取大括号内容
4. 智能修复（缺失引号、多余逗号、截断、括号不匹配等 10+ 种修复手段）
5. 兜底救援：即使完全解析失败，也能生成一个最小可用结构

同时，每次 LLM 调用都有重试机制（自动重试 1 次），成功率有充分保障。

### Q4：你们接了 6 个模型，一个模型挂了怎么办？

**A**：多模型熔断切换机制就是为了应对这个场景。主模型（如 Ark）不可用时，可以手动或自动切换到 DeepSeek、SiliconFlow、Gemini 等备用模型。所有提供商通过统一的 LLM 适配层管理，切换不影响业务逻辑。

### Q5：你们只有提示词工程，没有真正的本地数据，这是一个"伪创新"吗？

**A**：这个问题正好给了我们解释的机会。

我们的理论创新体现在两个方面：

**一是技术架构创新**——"AI 生成 + 国家锚点"的双层模式本身就是一种创新。传统路径是建一个大型知识库然后做检索；我们的路径是"用权威数据做框，用 AI 能力做个性化"。前者维护成本高、更新慢；后者灵活、可扩展、越用越厚。

**二是理论体系创新**——我们在第二章和第五章已经详细阐述了"个人—社会—国家"三位一体的中国特色生涯规划体系，融合了霍兰德、职业锚等西方理论，以及家国情怀、义利兼顾、明德弘道、实践志向、国家战略需求、社会贡献预期等 6 个中国特色维度。这 7 条差异化成长路径的推荐算法是基于理论驱动的，不是简单的 AI 生成。

我们的创新不是"伪创新"，而是**选择了一条更务实的技术路径**。

### Q6：你们和 ChatGPT 直接问有什么区别？用户为什么不直接去问 AI？

**A**：核心区别在于**结构化程度**和**学习闭环**。

ChatGPT 是通用对话工具，回答是线性的、一次性的。而 SkillMap：
- **技能树结构化输出**：把学什么、先学什么、后学什么变成"看得见"的拓扑图
- **节点粒度对话**：围绕每个技能点做深度复盘，对话上下文精准锚定
- **进度追踪**：节点状态从 locked → available → in_progress → completed，每一步都有记录
- **时间线**：所有学习行为时间线化，形成可视化的成长轨迹

用户用 ChatGPT 就像"问路"，而用 SkillMap 就像"有了导航"——前者告诉你怎么走，后者帮你走完。

### Q7：你们的评测数据在哪？怎么证明效果？

**A**：目前我们的效果验证主要来自两个途径：

1. **提示词单元测试**：覆盖 20+ 个测试用例，涵盖所有边界情况和异常输入
2. **质量评估服务**（QualityAssessmentService）：对每棵生成的技能树做结构评分 + 内容评分，评分结果落库在 `tree_quality_scores` 表

短期改进计划：
- 增加 Beta 用户内测，收集真实使用反馈
- 建立评分统计看板，可视化展示生成质量趋势
- 引入 A/B 测试，对比不同 prompt 版本的效果

### Q8：你们项目里提到了"社会维度和国家维度"的评估，这些维度怎么量化的？

**A**：这些维度的量化做了**双层分离设计**。

**底层（数据处理）**：采用加权评分算法，每个维度 0-100 分，综合计算后得出 7 条路径的匹配度。维度的权重和算法参数是可配置的。

**上层（用户展示）**：用户看到的是通俗的文字说明，比如"你的家国情怀评分较高，建议关注国家战略导向的成长路线"。不会给用户展示原始的评分数据，避免信息过载。

这种"数据处理精确计算、用户展示通俗易懂"的双层分离，是我们理论创新的核心原则之一（第 5.4 节有说明）。
